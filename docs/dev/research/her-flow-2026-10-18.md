## The test that closes gaps 1, 3, 4 and 6: `tools/her_flow.py`

- **Setup.** This PC held to her speed, with slow_pc's CPU set, cap and stand-in game. The real `MainWindow` runs
  offscreen in a temp data folder, set up like hers: 完整模式, 手动, 直播模式 on, a 嘉宾 scene, about 350 black-list
  entries.
- **Input.** The screen copy returns a 1920x1080 frame holding the sample lobby (made-up names). The game window,
  foreground lock, 直播姬's scene file and the updater are stubbed. No window appears, no key is pressed, no sound plays.
- **The run.** `check_now()` is driven like her evening: short and long gaps, and one idle stretch.
- **What it measures:**
  - F1 to marks.
  - Game frames on time during the check and during the scene.
  - The longest main-thread stall, and the scene's frame cost.
  - The app's CPU between checks.
  - Memory growth.
  - 12/12 names, the expected marks, and where the mirror sits.
- **Calibration first.** v1.0.0 in this test must land near her log (F1 to marks about 2.3-2.7 s), or the test is wrong.

The full app start and close (gap 2) is a separate case. It must use its own single-copy name: `paths.instance_key()` is
one per Windows user, so a second copy would reach the user's running app.
